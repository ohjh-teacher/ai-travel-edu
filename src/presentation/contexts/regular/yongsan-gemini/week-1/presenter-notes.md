# 1주차 강사용 진행 메모

학생 화면에는 이 메모가 표시되지 않는다. 순서는 1교시 50분 → 휴식 10분 → 2교시 40분이다. Gemini가 만든 그림은 수업 중 실제 결과를 화면에 띄워 관찰한다. 예시 그림을 학생 작품이나 현장 생성 결과처럼 소개하지 않는다.

## 1교시 · 50분

| 슬라이드 | 시간 | 진행 |
| --- | ---: | --- |
| 1. 표지 | 1분 | 오늘은 상상한 장면을 말로 설명해 그림으로 만들고, 말을 바꾸면 결과가 어떻게 달라지는지 살핀다고 안내한다. |
| 2. AI 경험 | 2분 | “AI를 써 본 적 있나요?”라고 묻고 손들기나 짧은 자유 발표를 받는다. 즉시 정의를 말하지 않는다. |
| 3. 생활 속 AI | 2분 | 네 사례를 하나씩 가리키며 “이 중 해본 것은?”이라고 묻는다. 서비스 이름 암기보다 이미 접한 경험을 떠올리게 한다. |
| 4. AI란? | 2분 | 학생용 정의를 읽고 “사람과 똑같이 생각한다는 뜻은 아니에요. 사람이 만든 컴퓨터 기술이 여러 일을 하도록 학습한 거예요”라고 보충한다. 의식이나 마음이 있다고 단정하지 않는다. |
| 5. 생성형 AI | 2분 | 클릭할 때마다 답·이야기·그림 순으로 공개한다. 마지막에 새로운 내용을 만드는 AI를 생성형 AI라고 소개한다. 긴 기술 설명은 하지 않는다. |
| 6. Gemini | 1분 | 오늘 사용할 도구 이름만 알려준다. “축구하는 문어를 그려줘”를 아직 입력하지 말고 학생 예상만 받는다. |
| 7. 머릿속 생각 | 1분 | 서로 다른 문어를 상상할 수 있음을 학생 답에서 끌어낸다. AI도 말하지 않은 생각을 정확히 알 수 없다고 정리한다. |
| 8. 프롬프트 | 2분 | 학생이 원하는 것을 말이나 글로 알려주는 것이 프롬프트라고 설명한다. 공식처럼 외우게 하지 않는다. |
| 9. 첫 예상 | 2분 | 문어 색·장소·표정·공을 15~30초 상상하게 한 뒤 2~3명에게 듣는다. 예상에 정답을 정하지 않는다. |
| 11. 현장 시연 ① | 4분 | Gemini에 정확히 `축구하는 문어를 그려줘.`를 입력한다. 이름·학교·비밀번호는 입력하지 않는다고 먼저 확인한다. 생성 중 학생 예상 2~3개를 다시 듣는다. 생성이 지연되면 결과를 지어내지 말고 기다리는 동안 예상을 말하게 한다. |
| 12. 첫 결과 관찰 | 3분 | 실제 결과를 Gemini 화면에 띄운 채 색·장소·표정·공을 학생이 먼저 말하게 한다. 보이지 않는 요소는 없다고 기록한다. |
| 13. 말한 것과 안 말한 것 | 3분 | 문어·축구는 말했음을 확인한다. 그 밖의 요소는 실제 그림에서만 찾는다. 골대·관중 등이 없으면 있다고 단정하지 않는다. |
| 14. 이유 예상 | 2분 | “왜 내 생각과 다를까요?”를 먼저 묻는다. AI가 말한 내용을 바탕으로 빈 부분을 채워 결과를 만들 수 있다고 쉬운 말로 정리한다. |
| 18. 조건 추가 | 3분 | 누가·어디서·무엇을·모습·느낌을 학생과 함께 채운다. 문어 예시는 기존 수업의 핵심 활동이므로 그대로 유지한다. |
| 20. 프롬프트 비교 | 2분 | 두 문장을 소리 내어 읽고 어느 쪽이 더 또렷한지 묻는다. 자세한 말이 항상 완벽한 그림을 보장한다고 말하지 않는다. |
| 22. 현장 시연 ② | 4분 | 슬라이드의 두 번째 문장을 Gemini에 입력해 현장에서 새 그림을 만든다. 입력 전 이번 결과를 예상하게 한다. 지연되면 학생에게 달라질 부분을 말하게 하고 실제 결과가 나올 때까지 정답처럼 제시하지 않는다. |
| 23. 두 결과 비교 | 7분 | 첫 결과와 둘째 결과를 번갈아 또는 나란히 보여준다. 짝과 30초 이야기한 뒤 추가 조건의 반영 여부, 뜻밖의 변화를 발표하게 한다. 조건이 빠졌다면 그 자체가 관찰 결과다. |
| 24. 첫 발견 | 7분 | 학생에게 먼저 발견을 묻고 두 문장을 하나씩 공개한다. 빠른 학생은 “다른 조건 하나를 더한다면?”을 짝과 말해 본다. 1교시 결과를 정리하고 휴식으로 연결한다. |

## 휴식 · 10분

휴식 슬라이드를 띄운다. 컴퓨터와 화면에서 눈을 떼고 자리에서 잠깐 움직이게 한다.

## 2교시 · 40분

| 슬라이드 | 시간 | 진행 |
| --- | ---: | --- |
| 26. 낮→밤 예상 | 2분 | “밤으로만 바꾸면 무엇이 달라지고 무엇은 남을까요?”라고 묻는다. 문어·축구·운동장을 남길 요소로 생각하게 한다. |
| 27. 현장 시연 ③ | 3분 | **기존 문어 대화에서** `문어의 보라색과 축구하는 모습은 그대로 두고, 낮이었던 운동장 배경을 밤으로 바꿔줘.`를 입력한다. 기존 그림의 완전한 보존을 약속하지 않는다. |
| 28. 밤 결과 관찰 | 3분 | 바뀌라고 한 부분과 뜻밖에 바뀐 부분을 분리한다. 문어·공·자세·구도를 실제 화면에서 확인한다. |
| 29. 학생 수정 실습 | 4분 | 학생이 자기 그림에서 바꿀 한 가지를 적는다. “___은 그대로 두고, ___을 ___으로 바꿔줘”를 참고해 Gemini에 입력한다. 짧은 표현도 허용한다. |
| 30. 학생 비교 | 2분 | 학생이 처음과 수정 결과를 직접 보고 네 질문에 답한다. 생성 성공만으로 끝내지 않는다. |
| 31. A/B 한 조건 비교 | 2분 | 두 문장의 차이가 낮/밤뿐인지 학생이 찾아 말하게 한다. 이번 실험은 기존 그림 수정과 다른 새 생성 비교임을 알려준다. |
| 32. 현장 시연 ④ | 4분 | 가능하면 A와 B를 각각 새 Gemini 대화에서 생성한다. 빛·색과 뜻밖의 변화를 비교한다. 새 그림마다 문어 자세 등이 달라져도 오류로 치부하지 않고 관찰한다. 생성이 느리면 학생의 예상과 비교 기준부터 듣는다. |
| 34. 프롬프트 맞히기 | 3분 | 미리 준비한 우주비행사 그림을 보여주고 짝과 한 문장을 만든다. 이 그림은 **연습용 예시**이며 학생 작품이나 현장 Gemini 결과가 아님을 밝힌다. |
| 37. 개인 프롬프트 | 3분 | 다섯 질문에 단어나 짧은 표현으로 답하게 한다. 이어 하나의 문장으로 묶게 한다. 막히는 학생에게만 한 질문씩 도와준다. |
| 38. 개인 생성·관찰 | 4분 | 학생이 자기 프롬프트를 Gemini에 입력한다. 결과를 곧바로 통과시키지 말고 네 관찰 질문을 살펴보게 한다. 생성이 안 되면 입력 문장을 먼저 점검한다. |
| 40. 개인 수정·재비교 | 4분 | 마음에 들지 않는 한 부분 또는 추가할 한 부분을 골라 다시 요청한다. 처음 결과와 나란히 비교한다. 빠른 학생은 조건을 하나 더 바꿔 재시도한다. |
| 42. 안전 약속 | 2분 | 이미지 생성과 바로 연결해 다섯 금지 사례를 확인한다. 친구·유명인 얼굴 오용, 괴롭힘, 잔인·성적 이미지, 개인정보 입력을 허용하지 않는다. 판단이 어려우면 생성 전에 교사에게 묻게 한다. |
| 43. 발견 정리 | 2분 | 먼저 “무엇을 발견했나요?”를 묻고 학생 답을 기다린다. 클릭하며 다섯 문장을 하나씩 공개한다. |
| 45. 다음 시간 | 1분 | 다음 주에는 그림에서 AI 대화와 이야기 변화로 이어진다고 예고한다. |
| 46. 후기 QR | 1분 | 독립 후기 화면으로 가는 QR을 안내한다. 현재 후기 화면의 제출 기능 상태를 수업 전에 확인한다. 학생은 강의 사이트가 아닌 후기 작성 화면으로 이동한다. |

## 기존 화면 재배치 메모

아래 화면은 기존 웹 강의의 문구와 그림을 유지해 보강안 사이에 넣었다. 각 화면은 앞뒤 활동 시간에 포함해 짧게 진행한다.

| 페이지 | 기존 화면 | 진행 |
| --- | --- | --- |

| 7–8 | 머릿속 생각·프롬프트 | 기존 문구를 유지하고 보강안의 질문과 정의를 함께 보여준다. |
| 10 | 3초 안전 점검 | 첫 생성 전에 O와 X를 구분해 말하게 한다. |
| 15–17 | 목표 문어 그림·짧은 프롬프트 예시·비교 | 현장 결과를 관찰한 다음 기존 준비 그림을 보여준다. 준비 그림을 방금 생성한 결과라고 소개하지 않는다. |
| 19·21 | 다섯 가지 조건·긴 프롬프트 | 기존 문구를 그대로 읽고 현장 생성에 연결한다. |

| 35 | 우주비행사 예시 | 짝이 먼저 문장을 만들어 본 뒤 기존 다섯 조각 설명을 공개한다. |

| 44 | 기존 요약 | 학생 답을 먼저 들은 다음 기존 핵심 세 문장으로 정리한다. |
| 46 | 기존 후기 QR | 기존 질문 문구를 유지한다. 수업 전 제출 기능을 확인한다. |

## 수업 전 확인

- Gemini 로그인·이미지 생성 가능 여부와 인터넷 연결을 확인한다.
- 학생 작품을 미리 만든 결과로 대체하지 않는다. 현장 결과가 다르면 그 차이를 관찰 자료로 쓴다.
- 후기 QR과 실제 제출 기능의 상태를 확인한다. 제출이 비활성화되어 있다면 학생에게 QR 제출을 요청하지 않는다.
