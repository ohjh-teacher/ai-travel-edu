# 사이트 안정화 진행 현황

마지막 갱신: 2026-10-28 (한국 시간)

이 문서는 강의별 대화의 콘텐츠 작업과 공통 사이트 안정화 작업을 구분한다. 이 경계는 이전에 시작한 대화와 앞으로 시작할 모든 정규과정·특강 대화에 적용한다. 강의 내용은 각 과정의 작업에서 관리하고, 여기서는 공유 규칙·등록·후기·배포를 관리한다.

| 단계 | 상태 | 완료 기준 |
| --- | --- | --- |
| 1. 배포 규칙 분리 | 완료 | 과정 작업의 완료와 전체 사이트 게시를 구분하고, 미완성 강의가 있어도 안전하게 작업할 수 있다. |
| 2. 게시 대상 분리 | 완료 (로컬 검증) | 승인된 강의만 배포 폴더에 들어가고 미완성 경로는 빠진다. |
| 3. 과정 등록 규격 | 완료 (목록·경로) | 과정 ID·경로·상태가 검증되고 목록 링크와 일치한다. 관리자 연결은 4단계에서 다룬다. |
| 4. 후기와 개인정보 | 로컬 구현·운영 적용 대기 | 과정 ID·문항별 표시, Firebase 관리자 로그인, 후기·사진 권한 규칙을 연결했다. 운영 계정 준비·규칙 배포·실제 권한 시험이 남았다. |
| 5. 자료 재처리 방지 | 완료 (로컬 판정) | 해시 판정 도구를 접수 절차에 연결하고 재사용·입력 변경·처리 방식 변경 시험을 통과했다. |

## 확인된 현재 상태

- 사이트의 공통 규칙은 `PROJECT_RULES.md`, 구조 설명은 `docs/architecture.md`에 있다.
- Firebase Hosting의 공개 폴더를 생성된 `dist`로 변경했다. 배포 전 검증·생성 단계가 실패하면 배포가 중단된다. 2026-10-05 공통 보안·관리자 화면을 Firebase Hosting에 배포했다.
- 동작구 취업특강은 작업 중이며 `동작취업지원센터` 대화에서 완성·배포한다. 용산 정규과정은 공개 대상이며 GitHub push와 Firebase 배포는 용산 대화에서 맡는다.
- 모든 과정 대화는 루트 `AGENTS.md`의 시작 점검에 따라 현재 Git 상태, 카탈로그, 매니페스트와 기존 구현을 확인한다. 오래된 대화의 기억만으로 동일 기능을 다시 구현하지 않는다.
- `content/catalog.json`에 게시 상태를 기록하고, 등록 검사에서 ID·경로·과정 카드 연결을 확인한다. 포털 카드는 여전히 HTML 원본에 작성되어 있으므로 새 과정은 카탈로그와 카드를 함께 등록해야 한다.
- 기존 스마트 여행·그림동화책·특강 후기의 새 기록에 `courseId`와 `questionVersion`을 넣는다. 관리자 화면은 이전 `lectureId` 기록도 조회하고, 새 `questionAnswers` 형식의 문항별 답을 표시한다. 용산 후기 양식은 해당 강의 대화에서 아직 연결해야 한다.
- 전체 과정 첫 화면에 `관리자 보기` 진입점을 두고 기존 공통 관리자 화면으로 연결했다. 스마트 여행 강의 화면의 관리자 버튼은 제거했다. 기존 관리자는 같은 후기 컬렉션에서 모든 과정의 기록을 조회·삭제한다.
- `firestore.rules`·`storage.rules`를 관리자 UID 문서 확인 방식으로 운영에 함께 배포했다. 관리자 화면은 기존 비밀번호 입력 방식을 유지하고, Firebase 이메일·비밀번호 인증 뒤 UID 권한을 확인한다. 사용자가 이메일·비밀번호 제공업체와 관리자 계정을 추가하고 `admins/{UID}` 문서를 저장했다고 보고했다. 로컬 관리자 로그인은 인증 성공까지 확인됐으며, 규칙 배포 후 관리자 조회 재시험은 대기 중이다. 비로그인 후기 조회는 운영 저장소에서 HTTP 403으로 거부된다. Google 제공업체는 켜졌지만 현재 사이트에서는 사용하지 않는다. 학생 이미지 업로드는 공개 다운로드 주소를 만들지 않는다.
- 공통 보안 게시에서 용산 강의 원본·카탈로그 상태를 건드리지 않도록 `config/publication.json`의 `heldCourseIds`에 용산을 기록했다. `node tools/release.mjs prepare`는 용산·동작구를 제외한 99개 파일로 통과했다. Firebase Hosting 배포 후 첫 화면과 관리자 경로는 HTTP 200, 용산·동작구 경로는 HTTP 404를 확인했다. 용산 대화에서 게시할 때 이 보류를 해제해야 한다.
- 보안 전환 상태는 `config/security-rollout.json`에서 `ready-for-hosting`이다. 사용자가 규칙 배포 후 로컬 관리자 대시보드가 열린 것을 확인했다. 비로그인 후기 조회는 HTTP 403으로 거부되고 공개 기관 목록은 HTTP 200으로 조회된다. 학생 후기·사진 제출과 삭제 권한 시험은 배포 후에도 남은 점검이다.
- 관리자 개인 이메일을 정적 사이트 소스에 넣어 이메일 입력을 없애는 시도는 자동 승인 검토에서 공개 노출 위험으로 거절되었고 적용되지 않았다. 현재 방식은 브라우저에서 최초 한 번 이메일을 입력해 기억한 뒤 이후 비밀번호만 입력한다. 개인 이메일을 소스에 우회해 넣지 않는다.
- 용산 대화에서는 후기 저장 코드를 적용하려는 시도가 자동 승인 검토에서 거절되었다. 이유는 이름·답변을 현재 공개 읽기가 가능한 저장소에 추가하는 것이었다. 용산의 독립 QR 화면 구조와 이 저장소 권한 문제는 별개다. 공통 인증·권한 전환 후 용산 후기 제출을 연결해야 한다.
- 자료 해시 판정 도구는 추출·OCR을 대신 실행하지 않는다. 작업자는 `status` 결과를 확인해 필요한 처리만 한 번 수행하고 `record`로 결과를 기록한다. 작은 시험 파일에서 최초 처리, 재사용, 처리 방식 변경, 입력 변경 판정이 기대대로 나왔다.

## 다음 공통 작업

1. 배포된 사이트에서 관리자 로그인과 기존 후기 조회를 확인한다.
2. 비로그인 삭제 거부, 학생 제출·사진 업로드, 관리자 삭제를 실제 운영에서 시험한다. 운영 데이터를 훼손하지 않도록 시험 기록을 사용한다.
3. 기존 사진 다운로드 토큰이 외부에 알려졌을 가능성을 점검하고 필요한 토큰을 폐기한다.
4. 용산 후기의 저장 연결과 문항별 답변 표시는 용산 강의 대화에서 완료한다. 동작구 강의 내용과 후기 연결은 `동작취업지원센터` 대화에서 완료한다.

## 과정별 push·배포 전 확인 (2026-10-04)

- 현재 공통 안정화 변경과 용산·동작구 과정 변경이 같은 작업 트리에 미커밋 상태로 함께 있다. 과정별 대화는 자신이 맡은 파일만 분리해 커밋·push해야 한다.
- 사용자 결정: 용산 대화창에서 우선 1주차 변경만 선별해 push한다. 이 push는 전체 과정 또는 사이트 배포 완료를 뜻하지 않는다. 동작취업지원센터 대화창은 내용을 더 보강한 뒤 해당 과정 변경을 push한다.
- 용산은 `published` 대상이지만 후기 화면은 아직 제출이 불가능한 미리보기다. 해당 대화에서 후기 완성·관리자 표시·권한 확인을 마친 뒤 게시한다.
- 동작구는 `draft`다. 해당 대화에서 강의안과 후기·링크 검증을 마치고 게시 상태를 변경한 뒤 배포한다.
- 공통 배포 설정과 지침이 Git에 반영되어야 새 worktree·복제본에서도 같은 규칙과 게시 산출물을 사용한다. 실제 Hosting 배포는 Git에 반영한 소스와 동일한 상태에서 `node tools/release.mjs prepare`가 통과한 뒤 `firebase deploy --only hosting`으로 한다.

## 작업 원칙

- 동작구·용산 강의의 본문과 자산은 이 안정화 작업에서 임의로 변경하지 않는다.
- 공유 파일의 변경은 기존 강의 링크와 URL을 유지하며 검증한다.
- 배포 전에는 배포 대상 목록, 공개 경로, 기존 후기 데이터 접근을 확인한다.

## 2026-10-28 게시 기록

- 동작구 취업지원 실무 특강을 published로 등록하고 강의 화면, 후기 제출 화면, QR 진입점을 연결했다. 기존 특강 후기 저장 코드와 공통 관리자 목록을 사용한다.

- 용산·청년 과정의 기존 원격 커밋을 통합한 codex/site-release-20261028 브랜치에서 66개 공개 파일 검증과 130개 게시 파일 검사를 통과했다. Firebase Hosting 배포 전 검사도 통과했고, https://aitraveledu.web.app 에 게시했다.
- 공개 첫 화면, 동작구 강의, 동작구 후기, 관리자 화면, 재설정 스크립트가 HTTP 200과 예상 내용을 반환했다. 운영 계정 로그인, 학생 후기 실제 제출·사진 업로드, 관리자 삭제는 이번 배포에서 실행하지 않았다.
